# Files tab downloads and sidebar draft inputs

Branch `backplane/files-download` adds downloads to the viewer's Files tab
(a file as itself, a folder as a zip). On `origin/main` c5a1b17f3 the
sidebar draft guard passes (175 source files, after 2e70a8cfa's
requalification, `phoneWebReview`). This branch changes five files in the
conservative sidebar import closure: `src/core/fm.bend`,
`src/core/icons.bend`, `src/core/msgs.bend`, `src/core/client.bend` and
`src/web/view.bend`. This note reviews each diff against
`scripts/sidebar-draft-inputs.json`'s concern: a new reader of composer
drafts, scratch fields or message body text inheriting the reduced private
image key. The manifest's `filesDownloadReview` records the same scope.

`src/core/fm.bend` gains a section of pure string functions after
`Fm.title`: the zip rules and their reading (`Fm.zip.rules`, `rule`,
`any`, `skip`, `kind`, `known`, `within`), what is stored
(`Fm.zip.stored`, `store`), entry and folder names (`Fm.zip.swap`,
`entry`, `char`, `clean`, `top`, `name`), the note's words
(`Fm.zip.note`, `note.head`, `why`), the download path check
(`Fm.drive`, `Fm.files.safe`), percent-encoding (`Fm.hex`, `plain`,
`pct`), the two URLs (`Fm.zip.url`, `Fm.get.url`) and the
Content-Disposition (`Fm.ascii.*`, `Fm.disposition`). It imports only
`./utf8.bend` beyond what it had. No def takes a `Ui`, a `M.State`, an
info map or a scratch key; each takes paths, names or thread ids as
strings. The defs above the section are byte for byte unchanged.

`src/core/icons.bend` adds two `IDef` entries (`download`,
`folder-down`: Lucide path data) to `Icon.all` and their names to
`Icon.used`. Icon data reads nothing.

`src/core/msgs.bend` is regenerated by `scripts/i18n-gen.py` from
`i18n/en.msg` and `i18n/ja.msg` with five new keys (`files.download`,
`files.download.tip`, `files.download.file`, `files.download.folder`,
`files.download.failed`): the five `T.files.download*` defs and the
generated key lists. The generated lookup modules (`msgs-lookup*.bend`,
`msgs-meta.bend`, not pinned) are reshaped around the new keys. Every
generated def maps a locale (and for two keys a name argument) to a
string; none reads state.

`src/core/client.bend` adds `Fm.down.url`, `Fm.down.k`, `Fm.down`,
`Fm.down.title.k`, `Fm.down.title` and `Fm.down.name` after `Fm.name`.
They read `Ui.sel` and, for the zip's name at a folder's root, the
selected thread's project title from `M.State` (`Ui.project_title`,
`Ui.thread_project`, `Ui.thread`, as `Ui.root.thread` already does). They
read no info map entry, no scratch field (`@...`), no composer draft and
no message or entry text, and change no state: each answers a URL or a
name string. Their callers are `View.fm.*` in `src/web/view.bend` and
`Files.json` in `src/mobile/view.bend`.

`src/web/view.bend` changes `View.fm.row.loc`, `View.fm.row`,
`View.fm.rows.loc`, `View.fm.rows`, `View.fm.body.loc` and `View.files`
(they now pass the `Ui` down so a row can name its download; main's
`disabled="disabled"` on an unopenable row is kept) and adds
`View.fm.dl.k`, `View.fm.dl` and `View.fm.row.dl`. The new nodes are an
`<a href download>` beside each row's button and one in the Files bar;
their attributes are `Fm.down`'s URL and `MSG.T.files.download*` text.
Nothing in the sidebar, the composer or the timeline is touched.

So the branch introduces no sidebar draft or body reader. It does not
change ordinary draft filtering, unknown `@` retention, the private image
key or cache slot, the closure scanner, transport inputs, recipient
ownership or authority, and no existing law changes meaning. The closure
itself is unchanged by this branch.
